# Ainur Karimov · CV

Сайт: https://ainureg.github.io/cv/ · [Русская версия](https://ainureg.github.io/cv/ru/)

**Источник данных — `content.json`.** Сайт и скачиваемый простой английский PDF собираются вместе. PDF — одна страница A4, шрифт 10,5 pt, поля 15 мм. Twenty Seconds сохранён отдельно: [инструкция](docs/TWENTY_SECONDS.md), ветка `archive/twenty-seconds`.

## Как обновлять

1. Изменить `content.json`.
2. Запустить `python scripts/build.py` для локальной проверки.
3. После проверки закоммитить изменения. При отправке в `main` GitHub Actions сам пересоберёт сайт и PDF из той же версии JSON, проверит их и опубликует вместе.

Локальные изменения не появляются на публичном сайте до push. Текущая настройка автоматизации подготовлена локально; для её работы в GitHub нужно опубликовать изменения.

## Где редактировать информацию

В `content.json` находятся:

- имя, специализация, локация, email, контакты, адрес сайта и фотография;
- `companies` — названия, сайты, логотипы и их официальные источники; `companyId` связывает работодателя с периодом работы;
- `experience` — роли, даты и короткие пункты `bullets.en` / `bullets.ru`;
- `presentations` — выступления; `presentationIds` связывает их с опытом и кейсами;
- образование, навыки, языки, публикация;
- подробные рабочие кейсы, дополнительное обучение и математические достижения для сайта.

Английские пункты опыта и выступлений используются в PDF без ручного копирования. Русские переводы для сайта редактируются рядом с английскими. Логотипы загружены с официальных сайтов, хранятся в `site/assets/logos/` и показываются рядом с названиями работодателей. PDF использует текстовые названия компаний.

Подробные кейсы, схемы, учебные мероприятия и группа навыков `id: interests` остаются на сайте; краткий PDF выводит профиль, весь опыт, публикацию, образование, основные навыки и языки. Это один PDF, без отдельных вариантов под вакансии.

## Как работает автоматизация

```text
content.json
    ├── HTML-шаблон → английская и русская версии сайта
    └── LaTeX-шаблон → простой одностраничный PDF
                         ↓
                 общий проверенный комплект → GitHub Pages
```

GitHub Pages раздаёт статические файлы и не запускает LaTeX на сервере при нажатии на кнопку. PDF заранее создаётся GitHub Actions при обновлении `main`. Посетитель сразу скачивает готовый файл. Ручная генерация и загрузка PDF не нужны.

Браузерная генерация PDF технически возможна, но требует отдельного JavaScript-генератора и повторной реализации макета. Для фиксированного одностраничного резюме используется генерация при сборке. Кнопка браузерной печати на сайте — дополнительная функция; она не подменяет скачиваемый PDF.

Полная сборка сначала готовит HTML и PDF во временной папке. Если PDF занимает больше одной страницы, есть переполнение, отсутствует логотип или не собирается HTML, прежний локальный комплект остаётся на месте. При ошибке в Actions новая версия не публикуется. Данные не обрезаются и шрифт не уменьшается автоматически.

`site/build.json` содержит хеш исходного JSON и хеши HTML/PDF. Команда `python scripts/check_bundle.py` проверяет, что данные и готовые файлы совпадают. Отдельной команды «обновить только сайт, оставив старый PDF» нет.

## Локальная сборка

Python 3.13+, стандартная библиотека. Для PDF на Ubuntu/Debian:

```bash
sudo apt-get install texlive-latex-base texlive-latex-recommended texlive-latex-extra texlive-fonts-recommended lmodern poppler-utils
python scripts/build.py
python scripts/check_bundle.py
python -m unittest discover -s tests -v
python -m http.server 8000 --directory site
```

Просмотр: http://localhost:8000/ (English), http://localhost:8000/ru/. Старый `/en/` также работает.

Результаты: `site/assets/ainur-karimov-cv.pdf`, `site/index.html`, `site/ru/index.html`. `generated/ainur-karimov-cv.tex` — экспорт для просмотра или отдельной ручной правки; следующая сборка его перезаписывает. `generated/` и `build/` не входят в Git. Подробные логи LaTeX — в `build/resume/` при отдельной отладке экспортера; при ошибке общей сборки диагностика выводится в терминал.

## Оформление и код

- `scripts/page.html` — HTML-шаблон; `site/styles.css` — оформление; `site/app.js` — интерактивность;
- `scripts/resume.tex.template` — простой PDF-макет, `scripts/resume.py` — его генератор;
- `scripts/content.py` — разрешение общих ссылок на компании и выступления;
- `scripts/build.py` — совместная сборка, `scripts/check_bundle.py` — проверка актуальности;
- `scripts/visuals/` — поясняющие схемы кейсов; это не реальные результаты моделей.

Исходники Twenty Seconds, его отдельный генератор и тяжёлые шрифтовые зависимости есть только в архивной ветке. [Как разово собрать его на текущих данных](docs/TWENTY_SECONDS.md).

## Публикация

Workflow `Publish resume` срабатывает после push в `main` и вручную через Actions. Он устанавливает инструменты, запускает тесты, собирает весь комплект, проверяет хеши, обновляет `gh-pages` одним коммитом и запрашивает сборку Pages.

GitHub Pages настроен на `gh-pages`, корень `/`. При необходимости восстановить: **Settings → Pages → Deploy from a branch → gh-pages → /(root)**.
